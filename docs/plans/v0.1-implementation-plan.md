## Conventions

- **Repo layout (target)**
  ```
  src/core/        schema.ts normalize.ts romanize.ts soundfold.ts dictionary.ts guides.ts memory.ts briefing.ts check.ts links.ts
  src/server/      server.ts  tools/*.ts  stdio.ts
  scripts/         build-data.ts validate-data.ts import-maknuune.ts issue-to-entry.ts
  data/            dialects/ guides/ entries/<dialect>/ sources.yaml LICENSE
  tests/           mirrors src/ and scripts/
  .github/         ISSUE_TEMPLATE/ workflows/ CODEOWNERS
  evals/           fallahi-prompts.md  en-us-prompts.md  tool-evals.xml
  ```
- **Commands:** `npm test` (Vitest), `npm run typecheck`, `npm run validate` (data), `npm run build` (data bundle + tsc).
- **Rule:** every task ends with `npm run typecheck && npm test` green before committing.
- **Commits:** conventional style (`feat:`, `test:`, `data:`, `docs:`, `ci:`).

## Milestone 1 — Foundation

### Task 1: Scaffold the project + verify SDK/Node compatibility ✅
- **Create:** `package.json` (ESM, `"engines": {"node": ">=20"}`, a `bin: openaccent-mcp` entry), `tsconfig.json` (strict, NodeNext), `vitest.config.ts`, `.gitignore`, `.nvmrc` (20).
- **Dependencies:**
  - Runtime: `@modelcontextprotocol/server` (v2), `zod@4`, `yaml`.
  - Dev: `typescript`, `vitest`, `tsx`, `@types/node`.
- **Steps**
  1. Add a smoke test `tests/smoke.test.ts` that imports the SDK and constructs a server.
  2. `npm test` passes.
  3. Check the Node version bundled with Claude Desktop (MCPB docs or manifest `server.mcp_config` notes). If it's under 20, switch to `@modelcontextprotocol/sdk@1.x` now and note it in `docs/design.md` §9.
- **Done when:** the smoke test passes, typecheck is clean, and the SDK choice is recorded.

### Task 2: Licenses and bilingual README ✅
- **Create**
  - `LICENSE`: MIT.
  - `data/LICENSE`: CC BY-SA 4.0 full text.
  - `README.md`: EN and AR sections covering what it is, status, how to install (placeholder), how to contribute (links to forms), and licenses.
- **Done when:** the README renders and both licenses are present.

### Task 3: Schemas (Zod) — dialect, entry, memory ✅
- **Create:** `src/core/schema.ts`, `tests/core/schema.test.ts`.
- **Tests first**
  - A valid fallahi entry parses.
  - A missing `word`, `dialect` or `meanings` is rejected.
  - A meaning with neither `ar` nor `en` is rejected.
  - `familiarity` defaults to `common`; an invalid value is rejected.
  - A dialect without `script` is rejected.
  - An `ajp` code normalizes to `apc`.
  - A memory file with an unknown `version` is rejected with a clear message.
- **Implement**
  - `DialectSchema` (with `script`), `EntrySchema` (with generic `romanized` and `familiarity`), `MemorySchema` (design §4.1, §4.2, §4.4).
  - Types via `z.infer`.
  - The cross-file rule (verified ⇒ reviewer listed) is **not** in the schema. It belongs to the validator (Task 5).
- **Done when:** all schema tests pass.

- **Create**

  - `data/sources.yaml` with the allowed and blocked sources (design §7).
- **Done when:** the files parse with `DialectSchema` (a test loads every file).

### Task 5: Data validator + CI ✅
- **Create:** `scripts/validate-data.ts`, `tests/scripts/validate-data.test.ts` (with fixtures under `tests/fixtures/data/`), `.github/workflows/ci.yml`.
- **Tests first.** The validator reports, with file path and reason:
  - schema errors
  - an unknown `dialect` or `parent`
  - a cycle in the dialect tree
  - `verified` without `verified_by`
  - a `verified_by` handle not in that dialect's `reviewers`
  - a duplicate `word` within the same dialect
  - an entry whose folder doesn't match its `dialect`
  - a `related` ID that doesn't exist
  - a dataset `source.name` that is blocked or not listed in `data/sources.yaml`
- **Implement:** exit code 1 on any error, and human-readable output.
- **CI:** on PR, run `npm ci`, `validate`, `typecheck`, `test`, `build`.
- **Done when:** fixtures cover every rule, and CI passes on the real data.

### Task 6: Build the data bundle ✅
- **Create:** `scripts/build-data.ts`, `tests/scripts/build-data.test.ts`.
- **Behavior**
  - Validate, then compile `dist/dictionary.json` = `{ version, builtAt, dialects[], entries[], guides{} }`.
  - Precompute search keys per entry (uses Tasks 9–11, so first implement it without keys, then wire the keys in Task 11).
- **Done when:** the bundle is deterministic (the same input gives the same output apart from `builtAt`), and it's included in `files` for npm/mcpb.

## Milestone 3 — Search core

### Task 9: Normalizers (Arabic + Latin) ✅
- **Create:** `src/core/normalize.ts` (`normalize(text, script)`), `tests/core/normalize.test.ts`.
- **Latin tests:** lowercase; accents stripped (`café`→`cafe`); `colour`/`color` and `realise`/`realize` fold to the same key; curly quotes straightened.
- **Arabic tests first**
  - Diacritics are stripped (`كَتَبَ`→`كتب`) and tatweel removed (`حـلو`→`حلو`).
  - `أ/إ/آ/ٱ` become `ا`.
  - `ى`→`ي`, `ة`→`ه`, `ؤ`→`و`, `ئ`→`ي`.
  - `٣`→`3`.
  - Whitespace and punctuation are trimmed.
  - The function is idempotent.
- **Done when:** the tests pass.

### Task 10: Romanization (Arabizi) + dialect sound folding ✅
- **Create:** `src/core/romanize.ts` (Arabizi is the Arabic implementation; other scripts can add theirs), `src/core/soundfold.ts`, and their tests.
- **Arabizi tests**
  - `7akoura` produces candidates that include `حاكوره`.
  - `3ashan`→`عشان`.
  - `5ubz`/`khubz`→`خبز`.
  - `sh`/`gh`/`kh` digraphs work.
  - Candidate lists are capped (e.g. ≤20).
- **Sound-fold tests (fallahi rules):**
  - `تشيف` and `كيف` produce the same key.
  - `كال` and `قال` produce the same key.
  - The rules come from the dialect's config (`soundRules` in the dialect YAML, optional), so other dialects can define their own.
- **Done when:** the tests pass, and `DialectSchema` gains an optional `sound_rules` field (list of `[from, to]` pairs).

### Task 11: Dictionary engine (load, inherit, lookup, express, list) ✅
- **Create:** `src/core/dictionary.ts`, `tests/core/dictionary.test.ts` (using a small fixture bundle).
- **Tests first**
  - `lookup('حاكورة', 'ar-ps-fallahi')` finds the entry.
  - `lookup('7akoura')` and `lookup('حاكوره')` find it too.
  - A word defined only in `ar-ps` is found when querying `ar-ps-fallahi` (inheritance).
  - A fallahi entry overrides the parent entry for the same word.
  - Verified ranks above draft; exact matches rank above fuzzy ones.
  - `express('now', 'ar-ps-fallahi')` returns fallahi entries whose glosses match.
  - `express('now', ['ar-ps-fallahi','ar-ps-madani'])` groups results by dialect.
  - `listDialects()` returns the tree with counts and verified %.
  - Results are paginated (`limit`, `offset`, `has_more`).
  - English: `lookup('y'all', 'en-us-south')` and `express('you all', 'en-us-general')` work with Latin normalization.
- **Decision:** search keys are computed when the dictionary loads (cheap at this size), not stored in the bundle. Revisit if load time becomes noticeable.
- **Done when:** the tests pass.

## Milestone 4 — Memory

### Task 12: File memory store ✅
- **Create:** `src/core/memory.ts` (a `MemoryStore` interface plus `FileMemoryStore`), `tests/core/memory.test.ts` (using a temp dir).
- **Tests first**
  - A missing file gives an empty memory.
  - `remember` adds profile, word, correction and style items with an `id` and `created_at`.
  - Saving the same correction twice doesn't duplicate it (idempotent).
  - `forget` works by ID and by text match, and returns what was removed.
  - Writes are atomic (temp file + rename).
  - A corrupt file is backed up to `memory.json.bak-<ts>`, the store starts empty, and a warning is surfaced (no crash).
  - The path is chosen from `OPENACCENT_MEMORY_PATH` if set, else `~/.openaccent/memory.json`.
- **Done when:** the tests pass.

### Task 13: Briefing + profile footer ✅
- **Create:** `src/core/guides.ts` (load, inherit and section-split guides) and `src/core/briefing.ts`, plus their tests.
- **Tests first**
  - The briefing includes the profile dialect's guide merged with its ancestors' guides (child sections first), plus personal words, corrections and style.
  - With no profile, the briefing returns an onboarding hint telling the model to ask the user's dialect and region and then call `remember`.
  - The footer is a single line under 200 characters listing the dialect and the top 3 corrections.
  - Personal words and corrections are marked as overriding the dictionary.
- **Done when:** the tests pass.

## Milestone 5 — MCP server

### Task 14: Server bootstrap (stdio) ✅
- **Create:** `src/server/server.ts` (`createServer({ dictionary, memory })`), `src/server/stdio.ts` (entry and bin), `tests/server/harness.ts` (in-memory client/server pair).
- **Tests first:** the client connects and lists 8 tools with the expected names and annotations.
- **Rule:** log to stderr only, never stdout.
- **Done when:** the harness test passes, and `node dist/server/stdio.js` starts.

### Task 15: Tools — lookup, express, list_dialects ✅
- **Create:** `src/server/tools/{lookup,express,list-dialects}.ts`, plus tests via the harness.
- **Each tool has**
  - the dialect defaulting to the profile dialect when omitted (the "dialect lock")
  - a Zod input schema with described fields
  - an `outputSchema`
  - `structuredContent` plus markdown text
  - draft results labeled `⚠ unverified`
  - the profile footer appended
  - actionable errors (e.g. an unknown dialect suggests close matches from `list_dialects`)
- **Done when:** the harness tests pass for success, empty-result and bad-input cases.

### Task 16: Tool — get_briefing ✅
- **Create:** `src/server/tools/get-briefing.ts` plus tests.
- **Description text** (it matters for model behavior): *"Call this FIRST at the start of any conversation where the user writes in or asks about a dialect. Returns who the user is, how they speak, their past corrections, and the dialect guide."*
- **Done when:** the tests cover both the onboarding case and the full-profile case.

### Task 17: Tools — remember, forget ✅
- **Create:** `src/server/tools/{remember,forget}.ts` plus tests.
- **remember:** input is a discriminated union `kind: profile | word | correction | style`. The description tells the model to call it whenever the user corrects its dialect.
- **forget:** marked `destructiveHint: true`. It returns the removed items.
- **Done when:** a round trip works (remember, then briefing shows it, then forget, then it's gone).

### Task 18: Tool — suggest_entry (pre-filled issue URL) ✅
- **Create:** `src/core/links.ts`, `src/server/tools/suggest-entry.ts`, plus tests.
- **Tests first**
  - The URL targets `https://github.com/c2do/openaccent/issues/new?template=add-word.yml` (or `fix-word.yml`).
  - Field IDs match the form IDs from Task 20.
  - Values are percent-encoded.
  - The URL is trimmed to under 2,000 characters; if it's too long, examples are dropped first and a note is added.
  - The output includes the "open in a browser, not the GitHub app" hint.
- **Description:** only call this after the user agrees to share.
- **Done when:** the tests pass.

### Task 18b: Tool — check_reply ✅
- **Create:** `src/core/check.ts`, `src/server/tools/check-reply.ts`, plus tests.
- **Tests first** (design §5, "check_reply in detail")
  - A fallahi-profile reply containing an Egyptian word that has a fallahi equivalent is flagged with the equivalent as the suggestion.
  - A word shared across dialects, with no distinct equivalent, is **not** flagged.
  - A `rare`/`dated` word is flagged.
  - A word from personal corrections (`wrong`) or personal words (`instead_of`) is flagged with the user's word.
  - 2–3-word phrases match.
  - English: an `en-us-general` reply with "delve" is flagged (via the avoid entry).
  - A clean reply returns an empty list and an "OK" verdict.
- **Description:** "Call before sending a reply written in a dialect; returns words to swap."
- **Done when:** the tests pass.

### Task 19: End-to-end integration test ✅
- **Create:** `tests/e2e/conversation.test.ts`.
- **Scenario**
  1. Briefing (onboarding).
  2. Remember the profile (fallahi).
  3. Look up `تشيف`, which finds `كيف`-family entries.
  4. Remember the correction `كويس`→`منيح`.
  5. A new server instance with the same memory file: the briefing contains the correction, and the footer is present.
  6. `check_reply` on a reply containing `كويس` flags it and suggests `منيح`.
  7. `suggest_entry` returns a valid URL.
- **Done when:** the test passes.

## Milestone 6 — Contribution system

### Task 20: Issue forms (bilingual)
- **Create**
  - `.github/ISSUE_TEMPLATE/add-word.yml`, `fix-word.yml`, `new-dialect.yml`, `become-reviewer.yml`, `config.yml` (blank issues disabled, with a link to the guide).
- **Rules**
  - Pre-fillable fields are `input`/`textarea` only.
  - Stable field IDs: `word`, `dialect`, `meaning_ar`, `meaning_en`, `example`, `spellings`, `romanized`, `register`, `familiarity`, `notes`.
  - Labels live in the YAML.
  - A required CC BY-SA checkbox.
  - Labels and descriptions are in both AR and EN.
- **Done when:** each form renders on GitHub (manual check), and a test asserts the field IDs match `links.ts`.

### Task 21: issue-to-PR bot
- **Create:** `scripts/issue-to-entry.ts` (pure function: issue body → entry YAML or a list of errors), `tests/scripts/issue-to-entry.test.ts`, `.github/workflows/issue-to-pr.yml`.
- **Tests first**
  - Parse the GitHub form body format (`### Label\n\nvalue`).
  - Handle `_No response_` as empty.
  - Missing required fields, an unknown dialect or a duplicate word each produce an error list.
  - A valid issue produces entry YAML with `status: draft`, `source.kind: contributor` and `added_by: <issue author>`.
- **Workflow**
  - Triggered on `issues: [opened, edited]` with label `add-word`/`fix-word`.
  - On errors, it comments with them in AR and EN.
  - On success, it creates branch `entry/<issue#>`, commits the file and opens a PR that closes the issue.
  - Permissions are minimal (`contents: write`, `pull-requests: write`, `issues: write`).
- **Merge step:** a workflow on PR merge sets `status: verified`, `verified_by: [merger]` when the merger is a listed reviewer of that dialect.
- **Done when:** the unit tests pass, and one real test issue on the repo goes end to end.

### Task 22: CODEOWNERS, contributing guides, branch protection notes
- **Create**
  - `.github/CODEOWNERS`: `data/countries/ps/ar-ps-fallahi*/** @c2do`, plus a default (the owner reviews other dialects' *format* until native reviewers join, but never marks them verified).
  - `CONTRIBUTING.md`: EN and AR.
  - `docs/adding-a-dialect.md`: step by step, with an example.
  - `docs/reviewing.md`: what "verified" means.
- **Owner step:** enable branch protection on `main` (require review plus CI).
- **Done when:** the docs are reviewed by the owner.
